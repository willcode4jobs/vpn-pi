# 05 — API surface & data model

All routes are served by the one `islandd` binary, bound to **wg0 only**. The
admin surface is the same server under `/admin`, guarded by an admin token. Wire
format is JSON (same canonicalisation as Phase One so envelopes verify).

## User App routes

| Method | Path | Purpose | newContextFile |
|---|---|---|---|
| GET | `/api/home` | island-mode state, wg status, local fail2ban entries, pending friend requests | 10, 11 |
| GET | `/api/friends` | list accepted friends | 7 |
| POST | `/api/friends/token` | issue a friend token (give) | 7, 8 |
| POST | `/api/friends/accept` | accept a received token | 7, 8 |
| GET | `/api/messages?peer=` | thread with a friend | 9 |
| POST | `/api/messages` | send a signed+sealed message to a friend | 9 |
| GET | `/api/files` | list files in the universal share (visible to friended members) | 9 |
| POST | `/api/files` | write a file to the universal share | 2, 9 |
| GET | `/api/files/{id}` | download a file from the share | 9 |
| GET | `/api/gate` | current gate state (gated / internet) | 10 |

> **Files live in the universal share on vega**, not per-node. A node's `/api/files`
> handler is a thin client to vega's share service (`core/store.ts` → vega's
> `core/share.ts`); only the request travels to vega, which is the service, not a
> relay (see [02](02-topology.md)). Friendship gates access. On a laptop demo
> (`--mock`) the share is in-memory locally.

## Admin routes (under `/admin`, admin-token required)

| Method | Path | Purpose | newContextFile |
|---|---|---|---|
| GET | `/admin/friends` | full friendship + pending view | 13 |
| DELETE | `/admin/friends/{id}` | **delete** a friendship (revoke) | 14, 15 |
| POST | `/admin/canary` | submit a signed+sealed canary prompt to the LLM gate | 16, 17, 18 |
| GET | `/admin/gate/log` | history of gate opens/closes | 16 |

> There is deliberately **no** `POST /admin/friends` (create). Forging friendships
> is impossible by omission, not by a guard — see [04](04-friending-protocol.md).

## Home payload (what the home view renders)

```jsonc
GET /api/home →
{
  "gate":     { "state": "island" | "internet", "closes_at": null | "<iso>" },
  "wg":       { "iface": "wg0", "peers": [ { "label", "wg0", "handshake_age_s", "up" } ] },
  "fail2ban": [ { "jail", "ip", "banned_at" } ],   // read LOCALLY on this node
  "requests": [ { "from_label", "from_pubkey", "received" } ]  // PENDING friends
}
```

- **fail2ban** entries are read from the *local* node only (no cross-node
  aggregation in the skeleton). Source ports cleanly from Phase One's
  `sources/fail2ban.py`.
- **wg status** comes from parsing `wg show` for the wg0 peers + last-handshake age
  → "connectivity status" (newContextFile line 11).
- **requests** = the PENDING set from the friend state machine.

## On-disk state

**On every node** (`/var/lib/islandd/`) — local, per-node:

```
identity/                 # loaded, never generated by the daemon
  ed25519.key  ed25519.pub
  x25519.key   x25519.pub
admin.token               # hash of the admin token (gates /admin)
friends.db                # accepted friends: pubkeys, label, wg0, since
pending.db                # received-but-not-accepted tokens (Home "requests")
offered.db                # tokens we issued, awaiting accept
messages/<peer>/…         # append-only, sealed message log per friend (P2P)
```

**On vega only** — the universal file share + gate audit:

```
island.db                 # the universal file share (REUSED from Phase One)
gate.log                  # open/close audit trail (vega is the gate)
```

## The universal file share (reuse vega's DB)

The share is **vega's existing SQLite DB carried over**, not rebuilt. polaris's
Phase One DB server is **deprecated** — vega is the sole file authority. The
existing `files` table is kept so current data survives the refactor:

```sql
CREATE TABLE files (              -- from Phase One db.py, reused as-is
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  name          TEXT    NOT NULL,
  size          INTEGER NOT NULL,
  node          TEXT    NOT NULL,   -- who added it (Phase One stored wg0 IP)
  content_type  TEXT,
  content       BLOB    NOT NULL,
  modified      TEXT    NOT NULL    -- ISO 8601 UTC
);
```

The only Phase Two change is **who may touch it**: access is gated by friendship
(verified identity), not by the old wg0-IP allowlist. Whether `node` becomes the
adder's pubkey/label and whether the share is fully-shared vs. scoped per friend
is in [08](08-open-questions.md).

Local-state storage engine (SQLite vs. flat files) is an
[open question](08-open-questions.md); the shapes above hold either way.

## "Single file" interpretation

newContextFile line 7 calls the App "a singular file." I read that as **one
executable the end user runs** (and one static web bundle it serves) — not literally
one `.ts`. `bun build --compile` already produces exactly that: a single
self-contained binary with the web UI bundled in. Flagged in [08](08-open-questions.md).
